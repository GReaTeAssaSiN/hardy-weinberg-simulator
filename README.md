# Симулятор Харди — Вайнберга

Учебный проект моделирования генетического равновесия популяции. Доступны **идеальная популяция, миграция, отбор, неслучайное скрещивание и генетический дрейф**, расчет на Python-сервере, графики и таблица по поколениям. Четыре фактора можно включать независимо.

## Запуск через Docker Compose

Запустите Docker Desktop или Docker Engine с Compose. Из корня `hardy-weinberg-simulator` выполните:

```bash
docker compose config --quiet
docker compose up --build --wait
docker compose ps
```

После готовности контейнеров откройте [интерфейс](http://127.0.0.1:8080/), [проверку сервера](http://127.0.0.1:8080/health) или [API Docs](http://127.0.0.1:8080/docs). nginx отдает собранный React и передает запросы к API в контейнер FastAPI. На компьютере доступен только порт веб-контейнера. Node.js и Python для этого способа работают внутри Docker.

По умолчанию сайт доступен только на компьютере запуска. Для показа в локальной сети или VPN задайте адрес нужного интерфейса машины с Docker. Например, в macOS или Linux:

```bash
WEB_BIND_ADDRESS=192.168.1.42 docker compose up --build --wait
```

Подставьте фактический адрес компьютера и откройте `http://192.168.1.42:8080/` со второго устройства в той же сети. При необходимости разрешите входящие соединения на этом порту в настройках компьютера. Если для локального запуска порт 8080 занят, используйте `WEB_PORT=8081 docker compose up --build --wait` и откройте `http://127.0.0.1:8081/`.

Посмотреть журналы и остановить проект:

```bash
docker compose logs --tail=50
docker compose down
```

## Что необходимо для разработки без Docker

- Python 3.12 или новее. Зафиксированные версии NumPy и SciPy требуют Python 3.12 или новее.
- Node.js 24 и npm.
- Установленные зависимости из `requirements.txt` и `web/package-lock.json`.

Клонируйте репозиторий и перейдите в папку проекта:

```bash
git clone https://github.com/GReaTeAssaSiN/hardy-weinberg-simulator.git
cd hardy-weinberg-simulator
```

Создайте виртуальное окружение и установите зависимости Python.

Для macOS и Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --cache-dir .cache/pip -r requirements.txt
```

Для Windows в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --cache-dir .cache/pip -r requirements.txt
```

Установите зависимости интерфейса (все платформы):

```bash
cd web
npm ci --cache ../.cache/npm
```

Окружение `.venv`, `node_modules` и кэши находятся внутри проекта и не включаются в Git.

## Запуск для разработки без Docker

Нужны **два окна терминала**. В каждом перейдите в папку клонированного проекта `hardy-weinberg-simulator`. Node.js и npm должны быть доступны в терминале.

1. В первом окне запустите сервер. Для macOS и Linux:

   ```bash
   .venv/bin/python -m uvicorn api.main:app --host 127.0.0.1 --port 8000
   ```

   Для Windows в PowerShell:

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8000
   ```

   Ожидается сообщение `Uvicorn running on http://127.0.0.1:8000`. Проверка сервера: откройте в браузере `http://127.0.0.1:8000/health` — должен появиться `{"status":"ok"}`.

2. Во втором окне запустите интерфейс:

   ```bash
   cd web
   npm --cache ../.cache/npm run dev
   ```

   Откройте адрес `Local`, который напечатает Vite (обычно `http://127.0.0.1:5173/`). Если порт занят, используйте выведенный Vite адрес.

3. Введите `N = 500`, `p = 0,3`, `T = 100` и нажмите **«Запустить»**. Ожидается постоянная частота `p = 0,3`, `q = 0,7`, доли генотипов `AA = 0,09`, `Aa = 0,42`, `aa = 0,49` и гетерозиготность `H = 0,42`.

4. Включите **«Миграция»**, задайте `m = 0,1` и `pₘ = 0,8` и запустите расчет еще раз. В таблице ожидаются `p = 0,3` в поколении 0, `p = 0,35` в поколении 1 и `p = 0,395` в поколении 2. На графике `p` приближается к `0,8`.

5. Выключите миграцию, включите **«Отбор»** и задайте `w₁₁ = 1`, `w₁₂ = 1`, `w₂₂ = 0,6`, `p* = 0,95`. При `p₀ = 0,3` и `T = 100` целевая частота впервые достигается в поколении **53**. Если включить оба фактора, в каждом поколении сначала применяется миграция, затем отбор.

6. Выключите миграцию и отбор. Задайте `p₀ = 0,5`, включите **«Неслучайное скрещивание»** и введите `F = 0,25`. В поколении 0 частоты генотипов равны `0,25 / 0,5 / 0,25`. Начиная с поколения 1 ожидаются `AA = 0,3125`, `Aa = 0,375`, `aa = 0,3125`. Сумма `AA + aa = 0,625`, а частоты аллелей остаются по `0,5`.

7. Выключите прочие факторы и включите **«Генетический дрейф»**. Задайте `N = 100`, `p₀ = 0,5`, `T = 200` и зерно `42`. В поколении 1 ожидается `p = 0,515`. На вкладке «Гетерозиготность» показаны траектория одного прогона и теоретическая средняя. Для этого N теоретическая средняя H уменьшается вдвое примерно за 138,3 поколения. Повторный запуск с теми же параметрами и зерном воспроизводит траекторию.

Для остановки нажмите **Control+C в каждом окне**. Серверы слушают только локальный компьютер.

## Проверка разработки

Из корня проекта, на macOS или Linux:

```bash
.venv/bin/python -m pytest
```

Для Windows в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Для интерфейса (все платформы):

```bash
cd web
npm --cache ../.cache/npm run test
npm --cache ../.cache/npm run build
```

Сборка создается в `web/dist`. Маршруты и схема API доступны по адресу `http://127.0.0.1:8000/docs` при запущенном сервере.

Для замера через запущенный Docker Compose выполните из корня проекта:

```bash
python3 scripts/benchmark_api.py
```

Скрипт измеряет время от отправки запроса до чтения ответа и выводит медиану и максимум пяти замеров после прогрева. Он проверяет один прогон с четырьмя факторами, серию из 100 прогонов дрейфа, обе выгрузки CSV и четыре одновременных запроса серии. Параметр `--url` меняет адрес приложения, `--repetitions` задает число замеров.

## Структура

- `core/ideal.py` — расчет идеальной популяции и генотипов при случайном скрещивании.
- `core/migration.py` — расчет изменения частоты аллеля при миграции.
- `core/selection.py` — расчет изменения частоты аллеля под действием отбора.
- `core/inbreeding.py` — расчет частот генотипов с учетом коэффициента инбридинга.
- `core/drift.py` — биномиальная выборка аллелей с помощью NumPy и теоретическое время снижения H вдвое.
- `core/batch.py` — статистика серии прогонов дрейфа.
- `core/chi_square.py` — отклонение модельных долей генотипов от равновесных пропорций по χ².
- `core/simulation.py` — общий расчет поколений, фиксации или потери аллеля и цели отбора.
- `api/main.py` — FastAPI, проверка данных и маршруты одиночного прогона и серии.
- `api/limits.py` — лимиты времени и числа одновременных расчетов.
- `web/` — React, TypeScript и интерфейс.
- `tests/` — проверки модели и API.
- `reference/`, `docs/` — каталоги для эталонных расчетов и документации следующих этапов.

Запрос к `POST /api/simulate` принимает необязательные объекты `"migration": {"m": 0.1, "p_m": 0.8}` и `"selection": {"w11": 1, "w12": 1, "w22": 0.6, "target_p": 0.95}`. При выключенных факторах выполняется расчет идеальной популяции. Если отбор включен и цель достигнута, ответ содержит `target_generation`. Для цели выше начальной частоты ищется первое поколение с `p ≥ p*`, для цели ниже — с `p ≤ p*`. Если цель совпадает с начальной частотой, возвращается поколение 0. При нулевой средней приспособленности API возвращает статус 422 с номером поколения. С дрейфом уже достигнутая граничная частота сохраняется при отсутствии нового притока аллелей.

Неслучайное скрещивание включается объектом `"inbreeding": {"f": 0.25}`. В поколении 0 генотипы рассчитаны по равновесным пропорциям. Начиная с поколения 1 поправка на `F` применяется к частотам после миграции и отбора. В ответе `h` — ожидаемая гетерозиготность `2pq`, а `f_Aa` — доля гетерозигот с учетом `F`.

Дрейф включается объектом `"drift": {"seed": 42}`. Зерно — целое число от 0 до 4 294 967 295. Если отправить `"drift": {}`, сервер выберет зерно и вернет его в `params.drift.seed`. Дрейф использует биномиальную выборку из `2N` копий по частоте после миграции и отбора. Итоговые доли генотипов вычисляются по частоте после выборки с учетом `F`. Это расчетные доли, поскольку выборка проводится по аллелям.

`drift_summary.boundary` содержит первое поколение, в котором `p = 0` или `p = 1`, включая начальное, если оно уже граничное. В последующих поколениях граничная частота сохраняется, пока миграция ее не изменит. Для чистого дрейфа с положительной начальной H возвращаются `h_theory` по поколениям и `drift_summary.theoretical_half_life`. Теория дает среднее по множеству прогонов.

Для каждого поколения с обоими аллелями API возвращает `rows[].chi_square`. Берутся расчетные численности `O = N × (f_AA, f_Aa, f_aa)` и сравниваются с ожидаемыми `E = N × (p², 2pq, q²)` без округления до целых. Это показатель отклонения внутри модели, а не проверка реальной выборки. При `p = 0` или `p = 1` χ² не определяется, поскольку часть ожидаемых численностей равна нулю. В `chi_square_summary` указаны порог 3,84, одна степень свободы и `first_exceedance_generation`, если порог был превышен.

Контрольный запрос в `/docs`: `{"n": 500, "p0": 0.5, "generations": 3, "inbreeding": {"f": 0.25}}`. В поколении 0 χ² = 0, в поколении 1 χ² = 31,25. Первое превышение порога приходится на поколение 1.

Серия запускается через `POST /api/simulate/batch`. Пример тела запроса:

```json
{"n": 50, "p0": 0.5, "generations": 100, "runs": 200, "drift": {"seed": 7}}
```

Дрейф включен всегда, допустимо 10–1000 прогонов. Остальные параметры факторов передаются так же, как в одиночном расчете. Если зерно не задано, сервер возвращает выбранное число в `params.drift.seed`. Повторный запрос с теми же параметрами и зерном воспроизводит всю серию.

В каждой строке `rows` есть средняя частота `p_mean`, границы коридора `p05` и `p95` (5-й и 95-й процентили частоты p) и средняя гетерозиготность `h_mean`. Для чистого дрейфа с положительной начальной H возвращается теоретическая `h_theory`, а при инбридинге — средняя доля гетерозигот `f_Aa_mean`. В `trajectories` хранятся значения p для первых восьми прогонов, включая поколение 0. Статистика `fixation` и `loss` учитывает только первое граничное событие каждого прогона и содержит число прогонов, долю и среднее поколение события, если оно наблюдалось.

Маршрут `POST /api/export` принимает объект с `params` и `rows` из результата любого из этих двух маршрутов и возвращает файл CSV. После расчета в интерфейсе нажмите **«Экспорт» → «Скачать CSV»**. В файле есть строка заголовков и все строки от поколения 0 до T. Поля разделены запятыми, десятичные числа записаны с точкой, отсутствующие показатели оставлены пустыми.

Три маршрута используют общий лимит в два одновременных запроса на процесс API. При занятых местах сервер отвечает 429 с `Retry-After: 1`. Лимит времени — 5 секунд для одиночного прогона и экспорта, 30 секунд для серии. При превышении сервер отвечает 504. Ошибки ввода возвращают 422.
